# MCP Feedback Collector 海外服务器部署说明

## 架构概述

在 Windows 上通过 Cursor SSH Remote 连接海外服务器开发时，每台服务器都部署了 **3 条兜底线**（1 条 stdio + 2 条 HTTP），和本地 Windows 的 3 条兜底互不冲突。

```
Windows 本地 Cursor（直接开发）:
  L1 primary   127.0.0.1:5050   (nssm 服务, HTTP)
  L2 backup    127.0.0.1:5051   (nssm 服务, HTTP)
  L3 stdio     127.0.0.1:5052   (Cursor 自 spawn)

Cursor SSH Remote 连服务器开发时:
  L1 primary   stdio 模式       (Cursor spawn，端口自动转发)
  L2 backup    127.0.0.1:<port>  (systemd, HTTP)
  L3 tertiary  127.0.0.1:<port>  (systemd, HTTP)
```

**为什么 primary 用 stdio？**
Cursor SSH Remote 只在检测到**新进程开端口**时才自动转发。stdio 模式下 Cursor 自己 spawn MCP 进程，
此时开的 Web UI 端口会被自动转发到 Windows，浏览器可以直接打开 feedback 页面。
HTTP 模式的 systemd 服务在 SSH 连接前就跑着了，Cursor 不会自动转发。

## 服务器端组件

每台服务器上有以下组件：

### 1. 应用代码
```
/opt/mcp-feedback-collector-web/
├── dist/           ← 编译后的代码
├── node_modules/
├── package.json
└── src/
```

### 2. Systemd 服务（3 个）
```
/etc/systemd/system/mcp-feedback-collector.service           # Primary
/etc/systemd/system/mcp-feedback-collector-backup.service    # Backup
/etc/systemd/system/mcp-feedback-collector-tertiary.service  # Tertiary
```

关键环境变量：
- `MCP_TRANSPORT_MODE=http`
- `MCP_SERVER_HOST=127.0.0.1`（仅 bind loopback，外网无法访问）
- `MCP_WEB_PORT=<对应端口>`
- `MCP_CORS_ORIGIN=http://127.0.0.1`

### 3. Cursor MCP 配置
```
/root/.cursor/mcp.json
```
注册了 3 条 HTTP 线指向本机端口。

## 常用运维命令

### 查看服务状态
```bash
systemctl status mcp-feedback-collector
systemctl status mcp-feedback-collector-backup
systemctl status mcp-feedback-collector-tertiary
```

### 重启服务
```bash
systemctl restart mcp-feedback-collector
systemctl restart mcp-feedback-collector-backup
systemctl restart mcp-feedback-collector-tertiary
```

### 健康检查（以日本 <PORT> 为例）
```bash
curl http://127.0.0.1:<PORT>/health
```

### 查看端口监听
```bash
ss -tnlp | grep -E ':(<PORT>)'
```

### 查看日志
```bash
tail -f /var/log/mcp-feedback-collector.out.log
tail -f /var/log/mcp-feedback-collector-backup.out.log
tail -f /var/log/mcp-feedback-collector-tertiary.out.log
```

## 更新代码

在 Windows 本地 build 后上传：

```powershell
# 1. 本地 build
cd F:\Project\mcp-feedback-collector-web
npm run build

# 2. 打包 dist
tar -C F:\Project\mcp-feedback-collector-web -czf dist.tar.gz dist

# 3. 通过 SSH MCP 上传到目标服务器
#    或手动 scp：
scp -P <SSH_PORT> dist.tar.gz root@<JP_SERVER_IP>:/tmp/

# 4. 在服务器上解压并重启
ssh -p <SSH_PORT> root@<JP_SERVER_IP>
tar -xzf /tmp/dist.tar.gz -C /opt/mcp-feedback-collector-web/
systemctl restart mcp-feedback-collector mcp-feedback-collector-backup mcp-feedback-collector-tertiary
```

## 熔断机制

前端 `app.js` 内置了熔断保护：

- 每次会话超时（默认 5 分钟），前端自动发送"用户在忙（第 N/5 次）"
- **连续超时 5 次**后触发熔断：发送"用户长时间未响应，任务结束。请终止会话"
- AI 收到熔断信号后应停止循环调用 feedback
- 用户手动提交反馈时，计数器自动重置

## 安全说明

- systemd 服务 bind `127.0.0.1`，外网无法直接访问
- stdio 模式的 Web UI 同样 bind 本机
- 4 台服务器防火墙默认 DROP 策略，互扫端口全部 BLOCKED（已验证）
- 访问方式仅限：Cursor SSH Remote 自动端口转发（SSH 加密隧道）
